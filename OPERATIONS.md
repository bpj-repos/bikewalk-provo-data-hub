## Restore in a clean checkout

Clone both private repositories without shallow history. A local no-hardlink clone from each primary checkout also works for the recovery drill. Use Python 3.9+ and Git. Set BWP_SOURCE_REPO to the absolute canonical BikeWalk clone. Run from the hub checkout. Use a new private temporary directory for each output.

    export BWP_SOURCE_REPO=/absolute/path/to/bikewalk-provo
    python3 -m unittest
    python3 build_hub.py "$BWP_SOURCE_REPO" /tmp/unique-staging-directory

## Prepare the next counts release

Save the unchanged delivery in durable private storage with its source, date and SHA-256. The collection lead reviews the transformation into a full annual UTF-8 slice using the pinned dictionary and checks every source field against the crosswalk. Keep original delivery, mapping and normalization instructions together. Use counts_candidate.py SOURCE_REPO RECEIPT_JSON NEW_PRIVATE_OUTPUT. The receipt contains version, change (compatible or correction), year, note, source (path, sha256, origin, received), slice (path, sha256), and mapping (an object keyed by original field, with slot, mode and breakdown for each measure). ## Promotion, failure and withdrawal

Before deployment check current team usage and expected transfer, record the current deployment ID and its Git commit, and verify historic pins and the current withdrawal list. Stage from the build_hub output only. Link the staging directory to the existing hub project, deploy with vercel deploy --prod --skip-domain, verify the staged catalog, files, hashes, MIME types and CORS, then promote that exact deployment. Recheck anonymously on the stable alias. Record the deployment ID, source receipt, reviewer and manifest pin. Public packages contain only approved resources. Archive private receipts, approvals and evidence outside the staging directory; never upload that parent. Restore from both Git remotes and the retained source backups, independently of Vercel history.

After a missed or failed check keep the catalog on the last good release. Record attempt time, last successful check, actual source date, error and retry owner. Counts refreshes on the next annual delivery or a correction. Safe Routes checks monthly. On hosting failure rebuild from the latest approved ledger, restage and verify. Repoint to a retained deployment only after checking its full tree against the current withdrawal list. For disclosure/rights withdrawal append dataset, version, date and a safe notice to withdrawn in releases.json, then deploy a clean tree. Check cited resource URLs return 404, purge caches and obsolete deployments where possible, and notify known consumers to remove local copies. Preserve the private audit trail. A previous Git commit or hosting deployment alone is unsafe to restore after withdrawal. Inventory shared hashes and affected records across all versions; withdraw every affected release. Check the restored tree for affected bytes, including identical resources cited under different versions.
