## Monthly refresh and reviewed publication

The Actions workflow “Monthly Safe Routes source review” runs at 14:41 UTC on the first of each month. Dispatch the same workflow in GitHub for an off-cycle update. It checks out main, acquires the three current UDOT school-plan layers and the approved July supplemental archive, rechecks Treeside and geographic/school-roster coverage, captures Provo's municipal polygon and existing Utah Bikeways within the buffered route extent, and checks the current PeopleForBikes Provo rating, published ways, residential speed default, analyzer release and Geofabrik Utah extract. A run builds locally modeled movement scores inside isolated digest-pinned containers. It records source checksums, observation dates, image identities and differences from the current release. The published BNA export serves as comparison data; locally modeled BNA is the primary score. The model refresh and the review job do not change production.

Run locally from the hub with Python 3.12, Shapely 2.1.2, pyproj 3.7.2, curl, Docker and an authenticated gh CLI: `python -m scripts.refresh_route_sources private/NEW_RUN`. Docker needs read access to the input directory. The Actions artifact retains its review, five-layer diff, dated source receipts, diagnostic leads, and candidate package for 30 days. Check provider freshness, school coverage, recalibrated Utah strata and source-switch disagreement counts. The crosswalk holds out entire named corridors and caps their weight at approximately 500 m. Small or conflicting strata retain the native Utah band. Review the sample size for each stratum and the continuity checks; agreement with BNA is not field validation. Short bracketed stretches on the same rated Utah and BNA ways can inherit the common BNA condition only within a 30 m fallback. Unrated segments stay unrated. `unrated-review.json` lists leads for optional verification. A failing provider or model run leaves the current hub and map available. Check Actions for failures, correct the cause and dispatch a fresh run.

The successful run summary prints its run number and candidate manifest SHA-256. This command independently rebuilds the package from its retained receipts, rejects obsolete or withdrawn versions, backs up inputs under a private release tag containing the version and the first 12 characters of its approved pin, records the immutable package and ledger, verifies the staged hub and then promotes it. Projects adopts those exact bytes; the command tests the app, verifies the five geometry hashes and a real crossing on a phone and desktop before and after map promotion. Its lock and run-specific checkpoints live under private/route-publication. Do not change the digest to bypass a failure. Rerun the same command after fixing a transient failure, and preserve the checkpoint directory. If a checkout has diverged, reconcile it without discarding others' work. If the artifact expires before review, dispatch another refresh. A refreshed dataset does not replace an older pin until publication. For rollback use the prior approved hub versions and the previous complete Projects deployment.

The refresh also writes a private comparison with the published Provo BNA download. It compares only compatible directions/geometry on the same OSM way and reports unmatched mileage/directions separately. Interpret differences with both input vintages in view. The continuity report counts all adjacent BNA/Utah switches and the smaller subset of qualifying through movements on the same Utah feature. An actual crossing, a turn or an unrated gap is not smoothed for visual continuity. Each fresh run includes its calibration strata in public sources.json and reports the private diagnostics with the candidate. None of those research leads is applied as a rating merely because the route is school-designated.
