# Who owns a data change?

Use this contract when a change touches BikeWalk Provo Data Hub releases, BikeWalk Provo Projects or Provo Streets Watch. Ownership follows the meaning of the operation. Physical storage, the first app to need a field, and the number of consumers do not decide who owns it.

| Proposed change | Implement it here | Example |
|---|---|---|
| Receive a delivery or amend a source record | The source steward owns its original system. The hub maintainer preserves the received snapshot and can issue a documented correction to the official dataset. | Keep the ArcGIS extract as received. In counts 1.0.1 the hub derives the official combined scooter count from both observed sessions. |
| Normalize, deduplicate, reconcile identities, define missingness, or add a shared derived field | Hub adapter and dataset contract. Record inputs, rule, units, uncertainty and verification. Release a new version so every consumer can reproduce the result. | The hub decides when a stored zero is observed and when an absent session makes a combined total unresolved. |
| Extend a record for an application | Store the extension in the consuming app, keyed to the appropriate source identity and release. Document its meaning and handle unmatched IDs on adoption. | Streets Watch owns which crashes belong to a concern, along with reports, moderation and notices. It imports approved crash details when available. |
| Shape, sort, filter, aggregate or index data for one view | Consuming app, using the pinned fields and their documented meanings. Name the selected population or denominator when it affects interpretation. | Projects can select 2026, sort stations, and chart scooter totals. A researcher can filter to one session. The official scooter formula belongs in the hub. |
| Publish an official subset, statistic, or reusable query shortcut | Hub when membership, aggregation or disclosure becomes part of the published dataset contract. A consumer-specific cache, index, saved filter or pagination helper stays local. | A year CSV is a hub resource whose rows must equal that slice of the complete series. A map viewport filter belongs to the map. |
| Improve a definition or fix a suspected error | Report the pin, affected fields/records, evidence and expected result to the owner of the rule. A consumer may label an uncertainty or suppress a disputed display while it awaits the corrected pin. | A local exploratory estimate carries its own label and method. Before presenting it as an official measure, have the hub document, validate and release it. |
| Hide, delete, withdraw or supersede data | Apps own their visibility rules, user records and local copies. The hub owns membership in releases, removals and withdrawal notices. The source steward owns deletion at origin. | Filtering out a station leaves it in the release. A record absent from a partial delivery needs investigation before the hub treats it as deleted. |

## Applying the contract

Only internal maintainers and update jobs write hub data. An app may write its own import, annotations and operational state. It adopts a release by pinning the manifest and checksum, verifying its files, comparing affected outputs and keeping a rollback path. No consumer import writes through to the hub. Reviewed app exports can become hub inputs through the private intake and disclosure process.

For a shared change, identify the dataset, authoritative field or rule, affected consumers and expected behavior on old pins. Use the dataset's version policy: corrections under existing definitions get a patch, compatible additions a minor release, and incompatible meanings, units or identities a major release. Document changed rows or coverage, validate a reproducible example, and promote the complete release. Consumers adopt independently. For privacy or rights withdrawals, follow the withdrawal procedure and have known consumers remove affected copies and caches; a rollback must respect the withdrawal.

During migration, record each existing calculation's current owner, intended owner and parity check. Move official rules to the hub when the consumer can adopt the verified pin. Record any deliberate local override, its reason and retirement condition. Projects now reads the corrected combined scooter measure from counts 1.0.1; its annual report, station table and trends share that hub value. Projects also adopts prepared incident-map interpretations without reimplementing source rules. Existing private BikeWalk ingestion and unmigrated datasets continue under their documented owners until their individual handoffs.

When ownership is ambiguous, write down the question the result answers. If changing the answer would change what a published record means, take it to the hub maintainer. If it changes what an app shows or does with the same record, take it to the app maintainer. A shortcut used by several consumers is a candidate for a documented shared resource; evaluate semantics, demand and cost before adding a hosted query endpoint.
